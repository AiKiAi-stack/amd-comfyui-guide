# 07 · 遇到的坑：按症状排障

跑起来出问题的时候，这一章帮你把看到的报错对到具体参数或文件。找和你现象一样的那一段，按顺序查完再动配置；验收标准是同一套命令和参数下问题不再出现，而且你看过实际结果。

## torch 一初始化就原生崩溃

独立装 ROCm 7.2 + torch 2.9.1 时，`torch.cuda.is_available()` 直接 Windows access violation。先跑 `scripts/check_gpu.py`；最小的张量运算都过不了，就别继续加载模型。现在这些成功图来自另一套 ROCm 7.14 环境，别当成 7.2 已经修好了。先把版本换回 [01 章](./01-hardware.md) 表里那套，再重新跑一遍检查。

## MOSS：HIPBLAS_STATUS_INVALID_VALUE

第一轮在 0/50 的 INT8 QKV 层就失败，报错里带着 gfx1032 kernel 缺失。先查 `code_source/gfx1032_quant_fallback` 的开关有没有显式打开：它走 ComfyUI 原有的反量化加浮点计算路径，只有你显式打开开关才生效。它没有替换权重，也没有补齐原生的 INT8 kernel，改变的只是这个进程里相关计算能力的选择。开关打开后重新跑，错误不再卡在 0/50 才算过这一步。

## MOSS：API 成功了，图却全是纹理噪声

API 返回成功，图却全是纹理噪声。先查采样节点：`ModelSamplingSD3` 被错误地设成了 timestep multiplier 1000。换成 `ModelSamplingAuraFlow`，保持 multiplier 1、shift 5，图就出来了。成功返回不等于采样配置对；旧的噪声图和 history 都留着，别覆盖。

## GGUF：第二次加载或卸载时 0xC0000005

Qwen 和 Z-Image 的 `GGMLTensor.to`、`partially_unload` 路径上都出现过原生异常，错误码 0xC0000005。先看它是不是在第二次加载或卸载时出现：关掉异步卸载只能规避一部分情况。Qwen 关掉 prefix cache 之后多参考成功了；Turbo-UN 还额外用了 CPU 文字编码、视觉编码和 CPU VAE。独立进程隔离确实有帮助，但这不能算根因修好。`fast-disk` 开关不等于关掉 GGUF 自己的 mmap，别把打开它当成已经绕开问题。

## Kroma：看着是 512，参考节点内部还是升到 1024

你把分辨率设成 512，参考节点内部还是升到了 1024，原参考路径 softmax OOM，进程 Aborted。先查参考链：改成独立的 `VAEEncode + ReferenceLatent`、512 参考之后能出图。能出图还不够，语义功能仍然要目视验收；降尺寸之后的图，别登记成原来那个 1024 任务的成功。

## FLUX.2：`--disable-pinned-memory` 会导致噪声

带 `--disable-pinned-memory` 启动时，两个「API 成功」的结果都是噪声图。先去掉这个参数：新服务恢复默认锁页内存之后，文生图和七项编辑都成功。这是这一套本机组合的对照，底层的 HIP/WDDM 根因还没定；Z-Image 某个配置能工作，也不能外推成 FLUX 正常。

## SSD、CPU 编码和「8GB 能跑」

实测时 D: 是 SATA HDD，G: 是 NVMe。后面成功的案例用了 G: 上的模型副本，同时也改了文字编码和动态显存配置，所以速度变化不能全记在 SSD 头上。8GB 的模型文件不是 8GB 的运行显存；16GB 系统内存也可能先成为瓶颈，CPU 编码也不一定更实用。判断速度变化来自哪一项时，先把同时改掉的文字编码和动态显存配置算进去。

## 修完怎么验收

1. 同一个输入重跑一次，问题不再出现，而且命令和参数和失败时是同一套。
2. 你记下了改的是哪一个参数或哪一个文件；只说「重启了一下就好了」不算。
3. 出新图了，且你已经看过这张图；只看 API 返回成功不算。
4. 失败的图和 history 还在，没有覆盖旧记录。

## 卡住了看哪里

- 显卡不在已验证的档位：[AMD 卡适配矩阵](./08-amd-matrix.md)。
