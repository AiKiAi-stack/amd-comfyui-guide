# 01 · 显卡、系统和版本

这一章不装任何东西。你先回答一个问题：这台机器能不能照着后面各章走，512×512、768、1024 三个尺寸里哪几个可以试。

答案从卡开始。对得上下面这张表，往下走；对不上，先读 [AMD 显卡适配矩阵](./08-amd-matrix.md)，别急着开始装。

## 动手前

一台已经装好显卡驱动的机器，加上下面这张对照表。表里是唯一一台完整跑通过整套流程的机器：RX 6650 XT、8 GB 显存。你的配置对得上，后面每一章都可以直接照做。

## 第 1 步：核对提交号

装完环境，在 ComfyUI 源码目录跑这两条：

```bash
# 在 ComfyUI 源码目录执行
git rev-parse HEAD
git -C custom_nodes/ComfyUI-GGUF rev-parse HEAD
```

两个值要分别等于表里的 `ce1e922d8623bb507180e32a0c01a7d0e29edef7` 和 `373048b8403a7820620065210a691263d4da0a61`。对不上，就别拿后面的图当参照，先把版本对齐。

## 第 2 步：确认三个尺寸在你这台机器上的边界

512×512 是主力尺寸。这套记录里绝大多数图都在这个尺寸上跑，8GB 显存先从这里试。

768 不是默认值。它只出现在早期基线和个别 Windows 记录里，比如 Qwen Base 的 768 文生图、旧的 768² 16 步基线。想试 768，按个案单独记一次，别直接改默认值。

1024 只在个案里成立。FLUX 1024 采样能跑完，到 CPU 解码时撞上内存保护，把 tile 改成 256、overlap 改成 64 分块解码才拿到图；Kroma 参考链内部升到 1024 时 OOM 了。所以别说「8GB 能跑 1024」，也别把 1024 当默认尺寸。

显存吃紧时先上分阶段隔离。文本编码、采样、CPU 解码各开一个进程，条件和 latent 通过归档传下去，具体见 [三阶段运行器](../../scripts/run_conditioned_repair.py) 和 [Qwen 参考阶段](../../scripts/run_qwen_reference_repair.py)。CPU VAE 默认打开（[start_ubuntu.sh](../../scripts/start_ubuntu.sh) 里的 `--cpu-vae`），拿时间换显存。

连续生成不要一次排太多。Z-Image 在同一个进程里连出三张已经验证过；Qwen pinned 第一次完整加载跑了十多分钟没完成，这时先停掉，分两批跑。单次成功说明不了长期稳定。

## 第 3 步：判断自己的机器属于哪一档

对照 [AMD 显卡适配矩阵](./08-amd-matrix.md) 的三档，先定位再决定从哪一步开始。

| 档位 | 怎么认 | 后面怎么走 |
| --- | --- | --- |
| 已验证 | RX 6650 XT（gfx1032），8 GB 显存 | 01 到 07 章按顺序做 |
| 同架构未验证 | RX 6600 / 6600 XT（同为 gfx1032） | 指令集相同、显存同为 8GB，但没有任何执行记录，不继承这张卡的结论 |
| 未验证 | RDNA1/2/3/4 的其他卡、核显（iGPU）、Instinct | 没有记录，既不当成可用，也不当成不可用 |

两个平台合计 162 条记录，Windows 95 条，Linux 67 条。数字只说明覆盖范围，不说明哪个平台更好。

Windows 那 95 条是原评价和案例、GPU 检查、分阶段规避和 768 基线。能看的成功图来自 ROCm 7.14 环境。更早那套独立的 ROCm 7.2 + torch 2.9.1，在 `torch.cuda.is_available()` 就出 access violation，至今没修，两套不能混着说。本机还留着早期 ROCm 7.2 包的安装元数据，那不代表旧栈能用。

Ubuntu 22.04.5 + ROCm 7.14 是唯一从全新独立环境走完「安装 → GPU 检查 → 出图 → 连续生成 → 回归」的一条路：Linux 40 项功能里 21 项通过、18 项部分达到、1 项没达到。

这不代表 Windows 不能用，也不代表 Ubuntu 换台机器一定成。两个平台的提示词、编码器、精度和进程方式都不一样，耗时不能拿来排名。条件允许优先 Ubuntu，它是唯一从全新独立环境走完全程的路径。

## 这份记录不覆盖的部分

- 别的显卡：只在 [AMD 显卡适配矩阵](./08-amd-matrix.md) 里分「已验证 / 同架构未验证 / 未验证」三档，没测过的卡不做兼容承诺。
- 别的模型权重：只测了 7 个模型系列、40 项功能，权重都钉在具体 revision 上。换量化版本或换权重，都是新实验。
- 画质上限：没做过最高质量参数搜索。512 到 768 是证据范围，不是推荐画质。
- 性能排名：平台、编译、驱动和缓存状态都没统一，文里的秒数不能横向比。
- 陌生机器上的全新安装验收：Windows 的从零步骤是整理出来的复现路径，完整安装还等着补齐；Ubuntu 有安装器，同样只在这一台机器上验过。

## 和你看到的不一样时

- 不知道自己卡的代号：装好驱动后跑 `rocminfo | grep gfx`，完整做法见 [AMD 显卡适配矩阵](./08-amd-matrix.md)。
- 提交号对不上：先把版本换成表里的提交，或者把差异单独记一次，别在旧结论上接着跑。
- 显卡不是 RX 6650 XT：直接读上面那张三档表，再到 08 章确认。
- 想知道某个数字是怎么来的：翻「证据与出处」里列的这几个文件。

## 过关条件

三条都能答上来，这一章就过了。

1. 你的显卡和系统能在对照表里找到对应行，或者你知道它落在三档的哪一档。
2. 装完环境后，`git rev-parse HEAD` 出来的提交和表里一致。
3. 你清楚 512×512 是这套记录的主力尺寸，768 和 1024 都要单独试。

三条都对上，就可以装环境了。Windows 走 [Windows 环境搭建](./02-windows-setup.md)，Linux 走 [Ubuntu + ROCm](./03-ubuntu-rocm.md)。装完用 [第一张图](./04-first-image.md) 验一次，再按需读 [模型选择](./05-models.md)、[工作流库](./06-workflows.md) 和 [排障](./07-troubleshooting.md)。
