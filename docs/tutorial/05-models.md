# 05 · 挑一个模型：各系列实测到什么程度

选模型之前，先知道每个系列实测到了哪一步。下面这些记录帮你缩小范围，最后的判断还是看证据：每项功能的最终图片、输入、提示词和结论都在 [总报告](../../report/feature-report.md) 里，选之前最好先扫一眼对应的卡片。

## Kroma Q2

低分辨率文生图能跑。风格参考会把主体一起复制过去，换头和多参考合成有局限。原参考链内部升到 1024 时 OOM 了，降低参考编码尺寸之后的结果另列。见 [早期测试](../../evidence/2026-10-18/README.md)。

## MOSS SFT / 8 步 DMD LoRA

加上 gfx1032 的 INT8 fallback、把时间尺度配对，就能出图。图生图的水彩要求只部分达到，简单的英文文字和布局提示另有独立案例。8 步这个配方是这台机器上的候选，我不宣称复现了作者没公开的完整参数。

## Qwen Image / Turbo / UN

文生图、参考编辑、局部重绘、多参考和姿态探索是分开记录的。CPU 文本编码和视觉编码、CPU VAE、关闭 prefix cache，是部分案例用的稳定性规避。「UN」这个命名不代表限制已经被证明解除；姿态参考也不是专用的 Pose Control 网络。

## FLUX.2 Klein

七项编辑各有独立证据。改色、图案迁移、双人合成和删除达到了各例的主要目标；风格、中文替换和二次编辑还有偏差。恢复默认锁页内存之后成功，禁用锁页内存产生的那些「API 成功但是噪声」的图也留着。见 [七项验收](../../evidence/2026-10-20-flux2-klein/README.md)。

## Z-Image AIO / GGUF

AIO 的 9 步、8 步、4 步，中英文，成年人体艺术探索，以及 GGUF 文生图，都有对应输出。GGUF 在同一个进程里发第二次请求时发生访问异常；换个独立服务重试成功，这不叫连续运行稳定。见 [完整记录](../../evidence/2026-10-20-zimage/README.md)。

## 证据与出处

这些结论的来源分几类：已核验的正文、索引标题、作者站外材料、上游文档，以及本机实验。早期多数微信文章没有读到全文，所以这里不是原文整合包的精确复现；Z-Image 的两篇离线正文和 FLUX.2 Klein 的来源边界，在各卡片里单列。仓库不转载文章全文。

## 怎么确认这一步成功了

1. 你选中的模型在 [总报告](../../report/feature-report.md) 里有对应卡片，卡片上写了结论是「通过」「部分达到」还是「未达到」。
2. 你知道这个模型是用哪套配置跑出来的，能对应上 [03 章](./03-ubuntu-rocm.md) 或 [02 章](./02-windows-setup.md) 里的启动参数。
3. 你手里有那个模型的权重和固定 revision，不是随便一个同名文件。

## 卡住了看哪里

- 想看某一项的真实输出：直接翻对应 evidence 目录里的 README 和图片。
- 模型下不下来：回 [第一张图](./04-first-image.md) 的下载那节，检查清单和路径。
- 挑好了模型但工作流打不开：去 [工作流库](./06-workflows.md)。
- 跑起来报错：先查 [排障](./07-troubleshooting.md)，再动手改配置。
